最近在练习一个智能数据分析 Agent 项目，从环境搭建到前后端联调完整跑通，收获比想象中多很多，想把它记录下来。

### 我练的这个项目是什么

项目叫 **shopkeeper-agent（电商问数）**：用户用自然语言提问，比如"统计华北地区的销售总额"，系统会先召回相关的字段、指标和字段取值，再由大模型分步推理、生成 SQL、执行查询，最后把结果以流式方式返回给前端。

它不是我之前想象的那种"调一次模型接口"的 demo，而是一条完整的工程链路：**数据准备 → 混合检索 → 智能体编排 → SQL 生成与执行 → 接口交付 → 前端展示**。

### 我学到了什么

这个项目把很多零散的知识点串了起来：

- **数据层**：用 MySQL 搭建教学数仓，把表、字段、指标等元数据整理成知识库
- **检索层**：Qdrant 做语义召回，Elasticsearch 做字段取值的全文检索，和结构化元数据配合，比单一检索靠谱得多
- **智能体层**：用 LangGraph 编排多阶段工作流——关键词抽取、多路召回、上下文构建、SQL 生成、校验、修正、执行
- **工程层**：FastAPI 提供接口，SSE 协议做流式返回，React 前端做聊天式界面，还有配置管理、依赖注入和日志追踪这些真实工程里必须考虑的东西

最大的感受是：以前写代码是"点对点"，模型接输入给输出；现在终于体会到什么叫"把一个 AI 应用做成产品"——中间每一步都有取舍，都要为稳定性负责。

### 踩过的小坑

练习过程中也遇到不少问题，最典型的是依赖版本冲突。项目原本锁定的 `asyncmy` 版本在我的 Python 3.14 环境里装不上，我把版本从 0.2.11 升到 0.2.14 才顺利解决。这种问题看起来小，实际排查起来却很锻炼人，也让我养成了看锁文件、查依赖关系的习惯。

另外这个项目本身是开源教程项目（来自 didilili 的《AI 智能体实战》系列），我在它的基础上 fork 出来学习，这里要感谢原作者把教程和代码整理得这么清楚，让我少走了很多弯路。
